# goci

`goci` is a command-line toolkit for common CI tasks in Go and Node.js projects. It includes commands for test reporting, module and service discovery, cross-compilation, Helm chart analysis, and supporting CI workflows.

## Installation

Install Go 1.24.2 or later, then clone and install the command:

```bash
git clone https://github.com/user-Xlll/go-ci.git
cd go-ci
go install ./cmd/goci
```

Make sure your Go bin directory is on `PATH` so the `goci` command is available.

## Commands

### Discover buildable services

List project services that can be built into container images:

```bash
goci show services --workdir="/path/to/project"
```

### Discover dependencies

List modules whose dependencies may need to be downloaded for an offline build:

```bash
goci show modules --workdir="/path/to/project"
```

### Generate test reports

Test reporting currently supports Go projects. Run it from the project directory:

```bash
cd /path/to/project
goci testreport /tmp/my-test-report
```

Or specify the project directory explicitly:

```bash
goci testreport --workdir="/path/to/project" /tmp/my-test-report
```

The output directory contains:

- `tests_report.json` — output from `go test -json ./...`.
- `coverprofile.txt` — test coverage data.
- `coverage.html` — an HTML view of source lines covered by tests.
- `cobertura.xml` — coverage data in Cobertura format, supported by many CI and code-quality systems.
- `junit.xml` — test results in JUnit XML format, supported by many CI systems.
- `tests.status` — `SUCCESS` when all tests pass, or `FAILED` with the modules containing failures.

For multi-module projects with a `go.work` file at the root, reports are written to separate module subdirectories and combined in the output directory root.

### Analyze Helm charts

`goci helm lint` analyzes a Helm chart and produces a SARIF report. It includes checks beyond the standard `helm lint` command, using a parser and analyzer with additional rules:

- `default-absent` — identifies required `.Values` references that are not defined in the chart's `values.yaml` and are not protected by a conditional or a `default` pipeline.
- `different-defaults` — identifies uses of the same `.Values` entry with different `default` pipelines.

### Cross-compile Go packages

Compile discovered packages for multiple platforms and generate Dockerfiles:

```bash
goci build --workdir="/path/to/project" /path/to/output
```

The output directory contains binaries for each discovered package and selected `GOOS`/`GOARCH` combination. Use `--platforms` to choose target platforms. A Dockerfile for `linux/amd64` is generated by default; disable it with `--dockerfile-platform=off`.

### Other available commands

- `goci sonar` runs `sonar-scanner` and waits for the Quality Gate result when no webhook is configured.
- `goci netrc` adds or removes credentials for HTTP/HTTPS hosts in the user's `.netrc` file.
- `goci authproxy` provides a Docker registry proxy that lets tests use temporary credentials while keeping registry credentials out of the test process.
- `goci containsdir` finds the smallest directory containing all specified files, with glob support. Use `--first-only` to return the first matching directory.
- `goci gitprevious` determines the previous release number from a branch or tag name, ignoring leading zeroes and supporting prefixes.
- `goci getmodules` downloads dependencies needed to build an application and run its tests.
- `goci nexus image-hash` retrieves the content hash for a container image from a Nexus repository.

For command and flag details, run:

```bash
goci --help
goci version
```
